# 3.7: remove the bridge

Roadmap 3.7, launch spec 6.1. The cutover (3.6) is done: `tasks.alipka.com` and its staging redirect to the one app,
and production runs `app.omark.app`. What kept the old instance running can go. Written 2026-10-30 in fast mode (no
approval wait).

## What changes for users

Nothing on `app.omark.app`, staging or the demo. Signed-in users stay signed in: the one app's cookies are already
`omark_*`. The sign-in helper's request header becomes `X-Omark-Auth`; a tab opened before the deploy gets a 403 on
its next token call, reads as offline (never signed out) and is right again once it reloads into the new version.

## In the code

1. **CI and Promote**: the `tasks-staging` job, Promote's `tasks` target and its `TASKS_*` variables, the `tasks`
   branches in `promote-check.mjs` and `release-notes.mjs`, and the bridge block of `.env.example`. Old tags and
   releases stay (launch spec 6.10).
2. **The whole-drive scope**: `ONEDRIVE_SCOPE=full` in `@omark/signin`, the `drive` root in `OneDriveAdapter` (its
   tests move to `approot`), `VITE_ONEDRIVE_SCOPE` in `apps/tasks`, the `full` branch of `check-signin.mjs`.
3. **Per-host folders and the legacy cache**: `VITE_PROD_FOLDER`/`VITE_STAGING_FOLDER`, `folderFor`,
   `legacyCacheApplies`, `migrateLegacyCache` and `migrateCache`. `apps/tasks` keeps `VITE_ONEDRIVE_FOLDER` (the real
   e2e uses it).
4. **Old hosts**: the standalone apps' links to `time.omark.app`, `tasks.omark.app` and their staging and demo hosts
   point at the one app's Settings. `tools/ci/redirect-sites.mjs` and its test go (the deployed redirects don't need
   it).
5. **Renames**: the CSRF header becomes `X-Omark-Auth`; in `apps/tasks`, the cookie
   prefix `taskapp` becomes `omarktasks` and the `taskapp:` storage names `omark-tasks:`. These only exist in the
   standalone build, which no host serves any more. The `__TASKAPP_*` test hooks stay (not user-facing).
6. **Local runs**: `pnpm dev` and `pnpm demo` run the one app's demo; `pnpm dev:signin` the one app with its helper.
   The root `functions/` stays for the standalone apps' real e2e (`pnpm e2e:real`), its comment says so.
7. **The owner grep** becomes a test (`tools/ci/test/owner-values.test.ts`): nothing outside `doc/history/` names
   the founder's hosts, folders, login or tenant. Done plans that only describe the bridge move to `doc/history/`;
   live docs are reworded. `.github/CODEOWNERS` is the one exception until the founder picks a team.
